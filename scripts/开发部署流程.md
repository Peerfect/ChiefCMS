## 完整部署流程

### 第1步：开发前 — 拉取线上最新数据到本地

> 目的：保证本地包含线上自动抓取的新闻等数据，避免部署时覆盖丢失

**服务器终端执行：**

```bash
cd /www/wwwroot/www.chiefbao.com
mysqldump -u chiefday -p123456 --set-gtid-purged=OFF chiefday > chiefday_backup.sql
```

**通过宝塔文件管理下载 `chiefday_backup.sql` 到本地 `D:\`**

**本地 cmd 执行：**

```cmd
mysql -u root -p123456 init < D:\chiefday_backup.sql
```

现在本地数据库就是线上最新的状态了，可以开始开发。

---

### 第2步：本地开发和测试

```cmd
cd D:\develop\CMS\ChanCMS
node --env-file=.env.dev app.js
```

浏览器访问 `http://localhost:3000` 进行开发测试。

---

### 第3步：查看改了哪些文件

在项目目录执行 git 命令查看改动：

```cmd
cd D:\develop\CMS\ChanCMS

:: 查看所有改动的文件列表
git status

:: 查看具体改了什么内容
git diff
```

git status 会列出所有修改、新增、删除的文件，比如：

```
modified:   app/modules/web/service/home.js
modified:   view/default/index.html
new file:   scripts/import-insurance.js
```

这样你就知道该上传哪些文件了。

---

### 第4步：导出本地数据库

**本地 cmd 执行：**

```cmd
mysqldump -u root -p123456 --set-gtid-purged=OFF init > D:\chiefbao_temp.sql
node -e "const fs=require('fs');let s=fs.readFileSync('D:\\chiefbao_temp.sql','utf8');s=s.replace(/utf8mb4_0900_ai_ci/g,'utf8mb4_general_ci');fs.writeFileSync('D:\\chiefbao_sync.sql',s,'utf8');"
```

---

### 第5步：部署到线上

#### 方式A：全量上传（不确定改了什么，最省心）

把整个项目压缩成 zip 上传覆盖。

**本地操作：**
1. 在项目目录右键压缩（排除 `node_modules`、`.git`、`public/uploads`）
2. 或者用命令压缩：

```cmd
cd D:\develop\CMS
powershell Compress-Archive -Path ChanCMS\app, ChanCMS\view, ChanCMS\config, ChanCMS\scripts, ChanCMS\public\view, ChanCMS\public\static, ChanCMS\pm2.json, ChanCMS\.env.prd, ChanCMS\package.json, ChanCMS\app.js -DestinationPath D:\deploy.zip -Force
```

**服务器操作：**
1. 宝塔上传 `deploy.zip` 到 `/www/wwwroot/www.chiefbao.com/`
2. 宝塔文件管理里右键解压覆盖
3. 如果 package.json 有变化：`npm install --omit=dev`

#### 方式B：只上传改动的文件（知道改了什么）

根据 `git status` 的结果，只上传对应的文件即可。

---

#### 导入数据库

把 `D:\chiefbao_sync.sql` 上传到 `/www/wwwroot/www.chiefbao.com/`

**服务器终端执行：**

```bash
cd /www/wwwroot/www.chiefbao.com
mysql -u chiefday -p123456 chiefday -N -e "SHOW TABLES;" | while read t; do mysql -u chiefday -p123456 chiefday -e "DROP TABLE \`$t\`;"; done
mysql -u chiefday -p123456 chiefday < chiefbao_sync.sql
rm chiefbao_sync.sql
```

---

#### 重启服务

```bash
pm2 restart ChanCMS
```

浏览器访问 `www.chiefbao.com` 确认正常。

---

## 一句话总结

```
开发前拉数据 → 本地开发 → git status看改动 → 导出数据库 → 上传代码+SQL → 清表导入 → 重启
```

---

## 不需要上传的文件/目录

| 文件/目录 | 原因 |
|----------|------|
| node_modules/ | 线上已安装，太大了 |
| .git/ | 版本管理用，线上不需要 |
| public/uploads/ | 线上用户上传的图片，覆盖会丢 |
| logs/ | 线上日志，不要覆盖 |
| data/ | SQLite数据，线上用MySQL |
| .env.dev | 开发环境配置，线上不需要 |
| chiefbao_sync.sql | 导入完就删 |

---

## 常见场景快速对照

| 场景 | 操作 |
|------|------|
| 只改了模板样式 | 上传 `view/` → `pm2 restart ChanCMS` |
| 只改了后端代码 | 上传 `app/` → `pm2 restart ChanCMS` |
| 新增了npm包 | 上传 `package.json` → 服务器 `npm install --omit=dev` → 重启 |
| 改了代码+数据库 | 上传代码+SQL → 清表导入 → 重启 |
| 不确定改了什么 | 全量上传代码+SQL → 清表导入 → 重启 |
| 只在后台改了文章 | 不用部署代码，只同步数据库 |
